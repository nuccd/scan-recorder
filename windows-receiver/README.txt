扫码记录 USB 接收程序 0.5.1（Windows 10/11 64 位，兼容手机 App 0.5.0）

1. 保持本目录文件放在一起，运行 scan-recorder-receiver.exe。
2. 手机通过可传输数据的 USB 线连接电脑，开启 USB 调试并授权这台电脑。
3. 手机打开“扫码记录 → 设置”，打开“扫码枪模式”，点击“应用并返回”，停留在扫码主页。
4. 电脑接收程序点击“刷新”，选择对应手机，点击“连接”，勾选“启用输入”。
5. 在 Excel 选好单元格，或在其他软件选好输入框。
6. 手机扫码，核对后“确认录入”。内容保存到手机，然后电脑输入原文并按一次 Enter。

Excel：请在输入前将录入列设置为“文本”，避免去掉前导零、长数字丢失精度或自动转换日期。
本程序按当前焦点输入，不会替你选择单元格，也不修改剪贴板。
Excel 回车后的移动方向遵守 Excel 自己的设置。

手机每条记录显示发送状态：
- 未发送：已保存在手机中，但未提交电脑。恢复连接不会自动补发。
- 已提交电脑：Windows 接受了键盘输入请求，仍请以目标软件实际显示为准。
- 发送结果待核对：可能已输入部分或全部内容，补发前请核对电脑，避免重复。
- 仅本机保存：包含换行、Tab、其他控制字符或超过长度限制，不自动输入电脑。

补发：先在电脑选好位置，再长按手机中相应记录，确认“发送到电脑”。
手动新增、编辑、撤销和批次切换不会自动向电脑发送；历史记录不会自动回放。
关闭手机扫码枪模式、离开手机扫码主页、取消电脑“启用输入”或退出接收程序可停止输入。
输入到以管理员运行的目标软件可能受到 Windows 权限限制；不要默认以管理员启动。

接收程序只使用本机 USB/ADB 通道，不连接外网，不保存扫码原文日志。
如果未随包提供 ADB，请在“ADB 路径”处选择公司允许使用的官方 adb.exe。
点击刷新会自动检查或启动 ADB 服务，然后搜索设备，不需要先打开控制台运行 adb。
启动 ADB 最多等待 12 秒，整个刷新最多等待 20 秒；超时或失败后恢复按钮并显示原因。
没有设备时检查 USB 调试、手机授权及公司允许的设备驱动；未授权和离线设备会单独提示。
不需要安装 Android Studio。
不需要自行安装 .NET 或 Visual C++ 运行库。系统必须为 Windows 10/11 64 位。

出现问题时打开“调试日志”，再点刷新，可实时看到当前步骤、等待阶段、进程 PID、耗时、退出码和 ADB 输出。
支持复制日志、保存 UTF-8 TXT、清空显示，以及关闭自动滚动后查看历史。
日志只保存在内存中，最多保留 400 条且总长度有限；需要保留时请手动保存。
日志含 ADB 路径、设备序列号和端口等连接信息，不含扫码原文。
主窗口与调试窗口每秒显示本接收程序自身的 CPU 和内存，不包含共享 ADB 服务或其他软件。
CPU 按整台电脑总算力归一化，物理内存为当前工作集；调试窗口另显示私有提交内存。
每 10 秒会将一条资源采样写入调试日志。

运行时只在本目录 receiver.ini 记住 ADB 路径；调试日志仅在用户点击保存时写入所选位置。
只有用户点击“复制日志”才会将调试日志放入剪贴板，扫码输入过程不修改剪贴板。
退出时只移除本程序创建的端口转发，不关闭其他工具使用的 ADB 服务。
随包 ADB 来自 Android SDK Platform-Tools，相关声明见 NOTICE.txt（若随包提供）。
