# 扫码记录（0.4.3）

`main` 统一维护一个「扫码记录」App，调优设置和诊断界面是常规功能。新启动时使用保存的默认变焦倍率，初始为 2.3×。入口、参数和构建说明见 [调优实操手册](scan-tuning.md)。文末按版本保留历史验证记录。

扫码记录 App 位于 `recorder` 模块（包名 `io.github.nuccd.scanrecorder`）。`quickie` 保留识别库，`sample` 保留上游示例。App 使用随 APK 提供的 ML Kit 模型，不需要联网下载模型。

统一 App 沿用原「扫码记录」包名，同包名、同签名覆盖安装可保留原批次和记录。旧独立调优 App（`io.github.nuccd.scanrecorder.tuning`）及其数据不会被删除，也不会自动迁移；需要的旧调优记录可在旧 App 内导出。

## 使用

1. 点击「批次」选择批次，或使用列表下方的「新建批次」按钮。选择「条形码」宽框或「二维码」方框，点击「开始扫码」并授权相机。
2. 将一个完整的码放入框内。框外及只有一部分在框内的码不参与录入；框内有多个不同内容的码时显示提示，等待用户对准其中一个。
3. 同一内容在 600 ms 的观察窗口内识别至少 3 帧且持续至少 200 ms 后，显示「已识别，待确认」及完整内容。允许最多 150 ms 的短暂漏识别，漏识别帧不计入次数；不同内容、多码或已解码但框外的结果会重置候选。核对标签后点击「确认录入」才保存；「取消录入」不保存。弹窗显示期间不接收新的录入候选。
4. 成功写入本地数据库后震动反馈，更新记录数。序号只显示在 App 列表中。
5. 点击列表记录可以修改或删除；删除后可撤销。手动新增也使用同样的重复规则。
6. 点击「导出 TXT」，在系统保存窗口选择手机的下载目录等位置，再通过公司允许的 USB 文件传输方式复制到电脑。

两种框只改变取景区域，都支持通用条形码和二维码。多帧一致性可以减少瞬时误识别，仍需核对实际标签；它不保证识别内容一定正确。

确认或取消后，请将刚才的码移出扫描框再扫。编辑、导出和切换批次时暂停扫码；进入后台时释放相机。待确认内容在旋转屏幕时保留，不会自动保存。已保存的数据在关闭 App 和重启手机后保留；卸载 App 或清除应用数据会删除本地数据库，请先导出。

手动输入窗口和软键盘收起后，扫描框自动按当前可用空间恢复尺寸，显示边界与实际扫码区域同步；保存和取消后均无需切换条形码 / 二维码模式来恢复。

## 小条码取景与对焦

- 开始扫码、相机就绪后，可用预览下方的倍率滑条调整相机变焦，旁边显示当前倍率。范围以设备相机实际支持的能力为准；相机未就绪、暂停或等待录入确认时无法调整。
- App 新启动采用保存的默认变焦倍率，初始为 2.3×，可在「调优」页输入 1.0–10.0 的有限小数；相机实际倍率按设备支持范围裁剪。
- 手动调整后，暂停继续和旋转屏幕保留当前倍率。仅修改其他调优参数时也保留当前倍率；修改默认变焦倍率并应用后，返回扫码使用新的倍率。恢复默认参数草稿会填回 2.3×，仍需应用才保存；取消不会改变已保存的设置。
- 点击预览中的标签位置进行对焦，标记显示对焦中及结果。设备不支持时提示不支持；对焦失败时可重新选择位置。短暂显示后标记自动隐藏，相机恢复默认的自动对焦。
- 小条码可先保持合适拍摄距离，调整倍率，再点击标签对焦。变焦不保证能恢复已模糊的条纹，反光、抖动及镜头最近对焦距离仍会影响结果。
- 点击对焦时先暂停候选分析，最多等待 300 ms 后允许新帧继续识别，不再一直等待对焦结果回报。对焦完成或变焦后重新累计候选，避免混用调整前后的识别结果。
- ML Kit 继续识别原有格式；连续扫码同时使用本地 ZXing-C++ 补充 9 种常用条形码格式，合并各引擎结果后统一检查扫码框、多码、稳定性及确认录入。标准条形码未解出时最多增加一次黑白反转尝试，不做 OCR 或内容纠正。正常与反色混排时不保证检出所有码，仍应一次只对准一个码。
- 保持现有分析分辨率选择策略。双引擎会增加单帧计算量，实际手持速度需要在标签、距离和光照相同的条件下验证。

排查识别问题时，可通过独立的 `SCAN_DIAG` 标签查看诊断信息：

```powershell
adb logcat -v raw -s SCAN_DIAG
```

每秒最多输出一份帧诊断，包含实际分析帧尺寸、旋转角度、双引擎处理到合并回调的耗时、解码数量、框内数量、不同内容数和本次扫码会话累计状态次数。解码数量包含不同引擎的相同结果，判断多码时按框内原文去重；首次原生解码成功另外输出数量及耗时，相机操控事件记录倍率及对焦结果。诊断不记录扫码原文，不影响 `SCAN_EXPORT` 的纯内容导出。

| 状态 | 含义 |
| --- | --- |
| `NO_DECODE` | 当前帧未解出非空文本 |
| `OUTSIDE_WINDOW` | 解码成功，但完整条码边界未落在扫描框内 |
| `MULTIPLE_VALUES` | 框内存在多个不同内容，等待对准其中一个 |
| `WAITING_FOR_STABILITY` | 框内有唯一内容，尚未满足多帧和时间要求 |
| `ALREADY_REPORTED` | 结果已经上报，等待该码移出后重新触发 |
| `REVIEW_PAUSED` | 正在确认上一条内容，暂停新候选 |
| `CAMERA_ADJUSTING` | 相机调整中，或此帧属于调整前的取景状态 |
| `TRANSFORM_UNAVAILABLE` | 预览坐标转换尚未就绪 |
| `DELIVERED` | 已送到待确认流程，尚不代表已保存 |

若累计 `NO_DECODE` 很高且其他状态始终为零，优先检查取景大小和清晰度；若有解码但主要是 `OUTSIDE_WINDOW`，检查完整码是否在框内；若反复 `WAITING_FOR_STABILITY` 而没有 `DELIVERED`，说明需要继续排查识别闪断。单张界面截图无法代替真实分析帧或连续日志。

## 批次管理与清空记录

- 「清空本批」只清除当前批次的扫码记录，保留批次名称，便于继续使用同一批次。
- 批次列表只显示已有批次，用于切换；列表较长时可在列表内滚动。列表下方提供「新建批次」「重命名当前批次」「删除当前批次」「删除全部批次」，操作按钮与批次名称分开显示。
- 重命名：先切换到要修改的批次，再点击「批次 → 重命名当前批次」。名称不能为空；修改名称保留批次中的记录、顺序及重复开关。
- 删除整个批次：先切换到要删除的批次，再点击「批次 → 删除当前批次」。确认窗口会显示批次名称和记录数量；点击「删除批次」才会删除批次及其全部记录。空批次也能删除。此操作与保留批次名称的「清空本批」不同。
- 批次列表以「（当前）」标记正在使用的批次。删除当前批次后自动切换到最近的其他批次，其他批次的记录保留。
- 「删除全部批次」会删除所有批次及其记录，确认窗口显示批次总数和所有批次的记录总数，取消不会修改数据。确认后新建一个空批次供继续扫码。
- 删除最后一个批次或全部批次时，会新建名为「新批次 · 时间」的空批次；确认窗口会提前说明。删除批次及清空记录均无法撤销，需要的数据请先导出。

## 记录与重复

- 接受通用文本扫码内容；不做 IMEI 校验或 IMEI1/IMEI2 处理，也不做 OCR。
- 内容原样保存，不转换数字、不去掉前导零、不修剪空格。
- 每个批次单独保存重复开关，默认关闭。内容完全一致才算重复。
- 重复扫码弹窗列出该内容在当前批次中已有的所有行号，例如「与已录入第 1、3 行重复」。关闭重复时不会新增，必须点击「确认，继续扫码」才能继续；打开重复时仍显示重复行号，由「确认录入」或「取消录入」决定是否新增。
- 开关仅影响后续新增和修改，既有重复记录保留。撤销删除恢复原记录及其位置。
- 同一扫码会话中，同一码不会每帧弹窗：必须离开扫描框至少 500 ms 后才能再次成为候选。弹窗期间继续跟踪其是否在框内。短暂识别闪断或处理帧较慢不会直接解除这个限制。
- UI 显示当前记录总数和不同内容数；手动录入也计入这些数字，因此它们并不自动等于实际手机台数。

## 导出格式

TXT 使用 UTF-8 和 Windows 换行（CRLF），按列表顺序每行一条。TXT 和 `SCAN_EXPORT` 日志均不含序号、标题、批次名或统计信息。

为保证多行二维码仍占一个物理行，导出时将反斜杠转为 `\\`、回车转为 `\r`、换行转为 `\n`。原始内容在数据库及编辑界面中保持不变。

日志导出步骤：先连接并授权 ADB，启动监听，再在 App 中点击「日志导出 → 输出记录」。

```powershell
adb logcat -v raw -s SCAN_EXPORT
```

批次和数量信息使用另一个标签 `SCAN_INFO`。logcat 是循环缓冲，不能作为持久存储；大量记录优先使用 TXT。为避免日志单条截断，本批如有转义后超过 3500 UTF-8 字节的内容，日志导出整体拒绝并提示改用 TXT。

TXT 在打开系统保存窗口前生成快照；旋转屏幕或系统回收进程后仍可使用这一快照完成保存。导出不会删除记录。

## 构建和测试

需要 JDK 17 或更高版本、SDK Platform 36、Build Tools 36.1.0。Windows 推荐通过脚本调用 Gradle Wrapper：

```powershell
# 默认构建包含调优功能的扫码记录 App（:recorder:assembleBundledDebug）：
.\scripts\build.ps1
.\scripts\build.ps1 -Tasks @(':recorder:testBundledDebugUnitTest', ':quickie:testBundledDebugUnitTest', ':recorder:lintBundledDebug', 'detekt', '--no-daemon')
# 连接测试手机或模拟器后，验证 SQLite、确认流程、弹窗及扫描框坐标：
.\scripts\build.ps1 -Tasks @(':recorder:connectedBundledDebugAndroidTest', ':quickie:connectedBundledDebugAndroidTest', '--no-daemon')
```

脚本自动寻找已安装的 JDK 17+，也可通过 `-JdkHome` 指定。Gradle 缓存放在项目的 `.gradle-user-home`，临时文件放在 `.local-temp`；项目位于 D 盘时这些数据也在 D 盘，不修改系统环境变量。使用 Android Studio 自身构建时，可将其 Gradle user home 配置为这个缓存目录。已有 SDK 仍使用 `local.properties` 指定的位置。

App 安装包位于 `recorder/build/outputs/apk/bundled/debug/recorder-bundled-debug.apk`，App 仪器测试包位于 `recorder/build/outputs/apk/androidTest/bundled/debug/`。不再单独构建 `tuning` App。本地 SDK 路径使用被 Git 忽略的 `local.properties`，不要提交个人 SDK 路径。

交付前真机检查：实际标签的识别和反光表现；横竖屏下框内、框外和多个码；条形码宽框和二维码方框；确认与取消、待确认时旋转屏幕；镜头停留与移开再扫；重复行号及重复开关；新增、修改、删除和撤销；切换批次；关闭重开和重启；拒绝权限；导出取消和失败；TXT 顺序、中文、前导零、数量以及日志无序号；释放相机后其他应用可使用相机。

Windows 实时接收程序留到后续阶段。
