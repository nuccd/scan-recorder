# 扫码记录使用手册（Android 0.5.0）

「扫码记录」用于连续识别通用条形码和二维码，人工确认后按批次保存在手机，也可导出 TXT / logcat，或通过 USB 将内容输入 Windows 当前输入框。完整功能总览见 [项目首页](../README.md)，电脑接收程序当前为 0.5.2。

App 包名为 `io.github.nuccd.scanrecorder`，`main` 只维护一个包含设置与调优功能的 App。ML Kit 模型随 APK 提供，ZXing-C++ 在本地补充一维码解码，不需要联网下载模型。最低 Android 版本为 6.0（API 23）。

## 1. 连续扫码与人工确认

1. 在「批次」中选择或新建一个批次。
2. 选择「条形码」宽框或「二维码」方框，点击「开始扫码」并允许相机权限。
3. 将一个完整的码放入白框，稳定识别后弹出待确认窗口。
4. 核对完整内容，点击「确认录入」保存；「取消录入」不增加记录。保存后更新计数、显示提示、提供触感反馈，并滚动到新记录。
5. 继续下一条。刚触发的同一码需移出白框至少 500 ms 才能在本次扫描会话中重新触发；需要休息时点击「暂停扫码」。

两种框只改变取景区域，不限制解码格式；识别范围在「设置 → 识别码制」中选择。默认支持以下 13 种格式：

| 类别 | 格式 |
| --- | --- |
| 一维条形码 | Code 128、Code 39、Code 93、Codabar、EAN-13、EAN-8、ITF、UPC-A、UPC-E |
| 二维格式 | QR Code、Data Matrix、PDF417、Aztec |

默认双引擎会合并 ML Kit 和原生一维码结果，再统一判断完整边界、框内不同内容数及稳定性。白框是结果接收范围，不表示引擎仅裁剪白框内图像解码。框内有多个不同内容时提示对准一个；同一帧两个引擎读出相同内容只算同一个结果。

默认需要至少 3 个成功帧一致，且观察至少 200 ms；还会考虑短暂漏识别和证据时效。参数可调整，见 [调优实操手册](scan-tuning.md)。多帧一致不能保证内容一定正确，仍应核对标签。

扫描时保持屏幕常亮。编辑、导出、进入设置或切换批次时暂停扫码；进入后台时释放相机。扫码和设置页固定竖屏，横放手机不会进入横屏界面；标签方向及分析帧旋转仍正常参与识别。

## 2. 变焦、对焦与补光

- **倍率滑条**：开始扫码且相机就绪后可手动变焦，旁边显示相机当前实际倍率。相机未就绪、暂停或等待确认时禁用相机交互。
- **默认倍率**：「设置 → 默认变焦倍率」初始为 2.3×，接受 1.0–10.0 的有限小数；相机不支持的值会按实际能力裁剪。
- **倍率恢复**：本次手动调整后，暂停继续及系统保存状态后的重建保留当前倍率。只修改其他参数不重置手动倍率；修改默认倍率并应用后，返回扫码时使用新倍率。
- **点击对焦**：点击预览中的目标位置进行对焦与测光，显示对焦中、成功、失败或不支持反馈；对焦标记短暂显示后隐藏。点击对焦后的候选等待时间默认最多 300 ms，不代表镜头一定在 300 ms 内对焦成功。
- **补光**：相机支持闪光灯时可切换补光；确认期间禁用相机交互。
- **布局恢复**：输入窗口或软键盘收起后，白框按当前空间重新测量，显示边界与实际接收区域同步，无需切换框形状来恢复。

小条码可调整距离、倍率、对焦位置和反光角度。原生引擎在首遍无结果时，可按设置增加一次灰度反色尝试；这不属于 OCR，也不修改保存的文本。实际速度需要用相同标签、光线、倍率和持握方式对比，不能仅凭截图或一次成功判断。

## 3. 记录、重复与数量

| 操作 | 说明 |
| --- | --- |
| 手动新增 | 点击「手动新增」，输入数字、中文、网址或多行文本后保存；空内容不能保存。 |
| 编辑 | 点击一条记录修改原文；输入框两侧保留间距，可显示多行。 |
| 删除与撤销 | 在编辑窗口点击「删除」，再通过底部提示中的「撤销」恢复原内容、顺序和发送状态。 |
| 界面序号 | 按当前列表从 1 连续显示；删除后重新编号。序号只在界面使用。 |
| 数量 | 显示当前批次总记录数和不同内容数；手动内容也计数，不自动等于实际手机台数。 |

内容按原文保存：不转成数字、不去掉前导零、不修剪空格，不做 IMEI 校验、IMEI1/IMEI2 处理或 OCR。

### 重复规则

- 「允许重复」按批次独立保存，新批次默认关闭。内容完全相同才算重复。
- 扫到重复内容时，窗口列出当前批次已有的所有行号，例如「与已录入第 1、3 行重复」。
- **禁止重复**：不会新增记录，必须点击「确认，继续扫码」确认提示后才能继续。
- **允许重复**：仍显示重复行号，可「确认录入」再次保存，也可取消。
- 手动新增和编辑也遵守当前重复开关。修改记录时不会把该记录自身的未变内容当成冲突。
- 改变开关不会删除已有重复记录；撤销删除恢复原记录及其位置。
- 同码移开 500 ms 的触发规则用于防止镜头停留时反复弹窗，与批次是否允许重复分别生效。暂停后重新开始是新的扫描会话。

## 4. 批次管理

点击「批次」后，列表只用于选择已有批次，并标记「（当前）」。列表下方独立提供管理按钮，批次较多时可在列表内滚动。

| 操作 | 结果 |
| --- | --- |
| 新建批次 | 默认提供时间名称，可修改后保存；自动切换到新批次。 |
| 重命名当前批次 | 名称不能为空；保留批次记录、原顺序和重复开关。 |
| 主页「清空本批」 | 只删除当前批次的记录，保留批次本身及名称。 |
| 删除当前批次 | 删除当前批次和其中全部记录；自动切换到最近的其他批次。空批次也可删除。 |
| 删除全部批次 | 删除全部批次及其记录，再建立一个空批次供继续使用。 |

删除当前批次、删除全部和清空记录都会先显示范围及数量，取消不会修改数据。删除最后一个批次时会新建「新批次 · 时间」，确认窗口提前说明。批次删除和清空操作不能撤销；单条记录删除提供短时撤销入口。

## 5. TXT 与 logcat 导出

### 导出 TXT

点击「导出 TXT」，按系统保存窗口选择文件位置。文件名包含批次名称与时间；文件内容不带批次名、序号、标题或统计。

- 编码为 UTF-8，使用 Windows 换行 CRLF，按当前列表顺序每条占一个物理行。
- 为容纳多行二维码，反斜杠转为 `\\`、回车转为 `\r`、换行转为 `\n`；编辑界面和数据库中的原文不变。
- 打开保存窗口前生成快照；系统保存状态后的重建可继续使用快照。取消、保存失败或完成导出都不会删除批次记录。
- TXT 保存后，可自行复制到电脑或其他位置；不需要运行 Windows 接收程序。

### 日志导出

连接并授权 ADB 后，先在电脑启动监听，再在手机点击「日志导出 → 输出记录」：

```powershell
adb logcat -v raw -s SCAN_EXPORT
```

`SCAN_EXPORT` 每条只输出与 TXT 相同的转义内容，不含序号。`SCAN_INFO` 单独记录导出开始、结束、批次及数量。logcat 是循环缓冲，不代替数据库；大量记录优先 TXT。若本批任意一条转义内容超过 3500 UTF-8 字节，日志导出会整体拒绝，并提示改用 TXT。

## 6. 设置与手机诊断

首页右上角「设置」包含 USB 扫码枪开关、识别引擎、码制、分析分辨率、默认倍率、稳定性及原生解码参数。只有一个统一 App，不需要安装独立调优版本。

- 「应用并返回」保存并应用设置；「取消并返回」或系统返回放弃未应用的修改。
- 「恢复默认参数草稿」将识别参数恢复默认、默认倍率填回 2.3×，同时将手机扫码枪模式草稿关闭；需再点击应用才改变已保存配置。
- 无效数值及仅原生一维码 / 仅 QR 的冲突组合会被阻止，参数修改不会删除记录。
- 主页诊断展示实际分析尺寸、倍率、两引擎与帧处理耗时、解码数量、框内数量、不同内容数和阶段计数；复制的完整报告另含设备、版本及全部参数。
- 「复制诊断」复制完整报告，不含扫码原文；「清零统计」重新累计诊断，不删除记录、不重启相机。

需要 logcat 排查时使用：

```powershell
adb logcat -v raw -s SCAN_DIAG
```

`SCAN_DIAG` 用于识别与相机元数据，`SCAN_EXPORT` 用于用户主动输出扫码内容；两者用途不同。诊断界面每秒最多更新一次，累计统计计入每个分析帧。详细参数、状态含义及实验模板见 [调优实操手册](scan-tuning.md)。

## 7. USB 输入电脑

手机「设置 → 扫码枪模式」首次默认关闭，应用后生效并记住选择。开启后，手机停留在扫码主页，通过 USB/ADB 与 Windows 接收程序连接。

确认一条新扫码后，先保存到本地，再向电脑发送原文并追加一次 Enter。Windows「启用输入」每次启动默认勾选，可手动暂停；目标可以是 Excel 单元格或其他软件当前输入框。

- 长按记录可手动发送或补发，包括已保存的手动记录；补发前需在电脑选好输入位置。
- 手机显示未发送、正在发送、已提交电脑、发送结果待核对或仅本机保存。发送失败不会删除手机记录。
- 断线、重连和重启不自动重放历史记录；取消扫码、手动新增、编辑、撤销及切换批次不自动发送。
- 含换行、Tab、控制字符、Unicode 行分隔符或超长内容只保存在手机；可用 TXT 导出。
- 进入后台或离开扫码主页会停止手机通道，返回后可重连。重连不会自动补发历史记录。

电脑端支持 ADB 自动准备、设备选择、超时和具体错误提示、实时调试窗口、日志复制 / 保存及 CPU / 内存显示。完整步骤、输入长度、Excel 设置、记录状态和错误排查见 [USB 扫码枪模式](windows-receiver.md)。

## 8. 数据保存与升级

批次、记录、顺序、重复开关与发送状态存于手机本地 SQLite，关闭 App 或重启手机后保留。单条修改和批次删除使用事务；删除全部与创建替换空批次一并执行，失败时回滚。

- 同包名、同签名覆盖安装可保留原数据；0.5.0 的数据库升级新增发送状态，不删除原记录。
- 系统保存状态后的重建可恢复待确认内容、当前倍率、未应用设置草稿和 TXT 导出快照；待确认内容不会自行保存。
- 卸载 App 或清除数据会删除数据库。系统备份已关闭，需要保留的批次请主动导出。
- 旧独立 `io.github.nuccd.scanrecorder.tuning` App 不会被统一 App 删除，数据和设置也不会自动迁移；旧记录可在旧 App 导出。

## 9. 构建与验证入口

Android 使用 JDK 17+、SDK Platform 36、Build Tools 36.1.0，调用项目脚本：

```powershell
.\scripts\build.ps1 -JdkHome '<本机 JDK 路径>'

# 单元测试与静态检查
.\scripts\build.ps1 -Tasks @(':recorder:testBundledDebugUnitTest', ':quickie:testBundledDebugUnitTest', ':recorder:lintBundledDebug', 'detekt', '--no-daemon')

# 连接测试手机或模拟器后运行仪器测试
.\scripts\build.ps1 -Tasks @(':recorder:connectedBundledDebugAndroidTest', ':quickie:connectedBundledDebugAndroidTest', '--no-daemon')
```

App APK 在 `recorder/build/outputs/apk/bundled/debug/recorder-bundled-debug.apk`，仪器测试包在 `recorder/build/outputs/apk/androidTest/bundled/debug/`。不再使用 `tuning` 构建类型。

脚本把 Gradle 缓存和临时文件放在项目 `.gradle-user-home` 与 `.local-temp`；模拟器数据使用 `build/avd`。项目在 D 盘时，后续测试数据也保存在 D 盘。已有 SDK 位置仍来自 `local.properties`，不提交个人 SDK 路径、缓存、数据库、APK 或真实扫码记录。

当前版本相关验证范围见 [Windows 与 Android 验证记录](windows-receiver.md#android-050-与首次接收程序验证记录)。现场标签的反光、单手持握与实际输入效果仍以实际测试为准。以下保留旧版本的原有验证记录，其中横屏或默认倍率等描述仅对应当时版本。

## 历史验证（0.4.1）
